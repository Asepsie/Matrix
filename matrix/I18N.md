## The layer (all in [src/core/i18n.js](src/core/i18n.js), loaded FIRST in `build.js` JS_FILES)

- `t('English string', vars?)` — key IS the English source. Lookup `DICT[lang][key]` →
  English fallback → the key itself. `{name}` placeholders via `vars`. Pure sync map lookup.
- `I18N_DICT = { fr:{…}, zh:{…} }` — `en` is implicit. Add translations here.
- Language persists in localStorage **`eim_lang`** (its own key — NOT app state, snapshots, or
  backups). `i18nSetLang(code)` persists + `location.reload()` (clean re-render, no stale
  strings). `i18nApplyLang(code)` sets it WITHOUT reload (tests only).
- `i18nApplyDom(document)` — boot sweep (in boot.js, on DOMContentLoaded) that translates
  **static index.html** markup via attributes (below).
- `i18nNum(n,opts)` / `i18nDate(d,opts)` — `Intl`-based, locale from `i18nLocale()`
  (`fr-FR`/`zh-CN`/`en-US`). Defined but **not yet wired** into existing formatters (Phase 3).
- Pseudo-locale `xx` (`i18nPseudo`) — set `localStorage.eim_lang='xx'` to expose truncation
  AND any untagged string (untagged stays plain ASCII).

## How to translate a string

**In JS render code** (`h+=\`…\``, template literals): wrap the visible text:
```js
h+=`<button>${t('SAVE')}</button>`;               // text
h+=`<input placeholder="${t('Name')}">`;          // attribute
h+=`<span title="${t('Delete engineer')}">×</span>`;
h+=`${t('{n} people · {g} groups',{n:a,g:b})}`;   // interpolation (NOT concatenation)
```
Then add the key to BOTH `fr` and `zh` in `I18N_DICT`. Run `node build.js` → audit shows
`N/N translated` (0 missing) when done.

**In static index.html** (can't call `t()`): tag the element, always with an EXPLICIT key
value (so the build audit sees it):
```html
<h2 data-i18n="⚙ SETTINGS">⚙ SETTINGS</h2>              <!-- textContent -->
<button data-i18n-title="Zoom in" title="Zoom in">＋</button>   <!-- title attr -->
<input data-i18n-ph="Name…" placeholder="Name…">         <!-- placeholder -->
<p data-i18n-html="… &lt;strong&gt;Settings&lt;/strong&gt; …">…</p>  <!-- innerHTML; entity-escape the < > -->
```
The `data-i18n-html` key holds the English HTML (entity-escaped in the attribute). The audit
decodes entities to match the JS dict key (which uses real `<strong>`).

## RULES / conventions (learned the hard way — don't violate)

1. **Never translate user data.** Anything editable + persisted stays as stored:
   project/engineer names, axis X name, factory defaults (`makeEngineer` "New Engineer",
   roster "Planning Resource", org "Open Position"), **quadrant labels** (`quadrantsByMode` —
   editable via Q-panel, saved), **org level names** (`_orgLevelNames` / `_LEVEL_DEFAULTS`),
   the "Resource Plan" res-title. Interpolated `escH(userValue)` stays exactly as-is.
   Fixed-chrome derivations ARE translated (e.g. `Y_LABELS`, the y-axis mode buttons).
2. **Seniority/keyword arrays are logic, not chrome.** In org.js, job titles like `'Tech
   Lead'`, `'Distinguished Engineer'`, `SENIORITY_ORDER2`, the `.indexOf(sn)` color arrays are
   matched against user role DATA — translating them BREAKS matching. Leave them. If you must
   show a translated label, translate at the DISPLAY site only (`escH(sn==='Not set'?t('Not
   set'):sn)`), never the key/logic.
3. **Toggle-button setters:** JS that rewrites a button's text must be `cond?t('X ON'):t('X
   OFF')`, NOT `t(cond?…)` — the audit's regex only sees a string-literal first arg, so a
   ternary inside `t(` hides the keys (and they'd read as orphaned). Each toggle state is its
   own key; the static markup uses the initial state as its `data-i18n` key.
4. **JS-rebuilt selects overwrite the boot sweep.** If JS does `sel.innerHTML='<option>All
   Groups…'` after boot, the `data-i18n` sweep is already done — wrap the JS string with `t()`
   too (e.g. org.js `All Groups`).
5. **FTE → ETP (fr) / 全职当量 (zh).** Keep this consistent across sections.
6. **`t()` does not escape.** It's developer text only; user data still flows through `escH()`.
   Never pass untrusted data as a `t()` key.
7. **Flat-bundle rules still apply:** no duplicate top-level decls; no `</script>` in strings;
   no dup keys within one language object (I removed dup `↖ SELECT`/`DRAW:` once).
8. **No apostrophe (`'`) in an English KEY.** The build audit unescapes `t('…')` call keys but
   does NOT unescape dict keys, so a key like `t('based on {name}\'s profile')` never matches
   its `'based on {name}\'s profile':…` dict entry → shows as `1 missing, 1 orphaned`. Reword
   the source string (e.g. `based on the profile of {name}`). VALUES may contain `\'` freely
   (only the KEY side must stay apostrophe-free). Same care for the possessive in EN prose.
9. **Loop-counter / param named `t` shadows the global `t()`.** SVG-heavy files use `for(var
   t=0;…)` axis-tick loops and `.forEach(t => …)` callbacks. Because `var` hoists function-wide,
   ANY `t('…')` call elsewhere in that same function throws `t is not a function` at RUNTIME
   (build's `vm.Script` parse does NOT catch it — only rendering the chart does). Before wrapping
   a string, grep the enclosing function for a local `t`; rename the loop var (`t`→`tk`) or don't
   wrap inside that scope. Bit us in `pfHistSvg` (portfolio.js). Always exercise the rendered tab
   in preview, not just the build audit.

## Validation & verification

  `data-i18n*` attr in index.html, reports `translated/total`, `missing`, `orphaned` per lang.
- **Tests:** [tests/i18n.test.js](tests/i18n.test.js) — fallback, interpolation, pseudo, Intl,
  placeholder parity. `node --test tests/*.test.js`.
- **Preview quirk:** the dev server (`serve matrix/dist`) serves the app at
  **`http://localhost:5599/matrix.html`** (root `/` is a dir listing). To test a language:
  `localStorage.setItem('eim_lang','fr')` (or `zh`/`xx`) then navigate/reload. Reset to `en`
  when done. `railGo`/`openOrgChart` etc. ARE callable from `preview_eval` (bundle globals).
